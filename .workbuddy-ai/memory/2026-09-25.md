# 2026-09-25

## Research: is any open-source ASR model better than Parakeet TDT 0.6B v3?

Asked by user (no code changes). Sources: HF Open ASR Leaderboard blog (2025-11-21), MarkTechPost
2026-07-23 roundup (figures verified against primary sources), model cards.

Findings worth keeping:
- Parakeet TDT 0.6B v3: 6.32% mean WER (English short-form), RTFx 3332.74, 25 EU languages +
  auto LID, CC-BY-4.0. Still the throughput leader among multilingual open models.
- More accurate, all slower: Granite Speech 4.1 2B (5.33%, RTFx 231, Apache-2.0, 6 ASR langs),
  Cohere Transcribe 2B (5.42%, Apache-2.0, 14 langs, no LID/timestamps, gated repo),
  Canary-Qwen-2.5B (5.63%, RTFx 418, CC-BY-4.0, English), Qwen3-ASR-1.7B (5.76%, Apache-2.0, 52 langs),
  Granite 4.1 2B-NAR (best both-axes candidate: ~1820 RTFx, ~5.65% on 7-set basis).
- Parakeet TDT 1.1B is a trap: English-only, 7.02% — worse than 0.6B v3.
- No Parakeet v4 exists as of this search.
- Streaming-native alternatives (different architecture, not batch): Voxtral Mini 4B Realtime
  (Apache-2.0, 13 langs, 80-1200 ms configurable delay), Kyutai STT 1B en/fr (CC-BY-4.0, 0.5 s delay
  + semantic VAD), microsoft/VibeVoice-ASR-Streaming-1.5B (MIT, 10 langs, speaker-attributed,
  released 2026-09-02, no WER in card).
- Leaderboard caveat: WER averages are not comparable across entries (TED-LIUM dropped by some,
  MOSS RL-fitted on leaderboard splits); Appen private tracks reorder the board.

Conclusion for this project: no drop-in replacement; parakeet v3 stays the right default for
CPU-first, low-latency dictation. Qwen3-ASR (already shipped here as ONNX 0.6B/1.7B) is the natural
second engine for CJK.

## Follow-up: NVIDIA Nemotron 3.5 ASR (asked 2026-09-25)

`nvidia/nemotron-3.5-asr-streaming-0.6b` (card date 2026-06-04; announced ~06-06). 600M,
Cache-Aware FastConformer-RNNT + prompt, 24 encoder layers. License OpenMDW-1.1 (HF API reports
license=other; commercial use stated OK, but a newer/unproven license). Extends
`nvidia/nemotron-speech-streaming-en-0.6b` (English-only, ~Jan 2026) with language-ID prompting.

- 40 locales in 3 tiers: 19 transcription-ready, 13 broad-coverage (32 out of the box), 8
  adaptation-ready (need fine-tune: el, he, lt, sl, lv, mt, th, nn).
- Native streaming, non-overlapping chunks, cache reuse. Latency knob = `att_context_size`:
  [56,0]=80ms, [56,1]=160ms, [56,3]=320ms, [56,6]=560ms, [56,13]=1.12s. Set at inference, no retrain.
- Built-in punctuation + capitalization; `target_lang=auto` emits a language tag; `strip_lang_tags`.
- Accuracy (avg WER, FLEURS): transcription-ready 10.38 (80ms) -> 8.84 (1.12s) with LangID;
  11.14 -> 9.21 auto-detect. Broad-coverage 25.86 -> 22.13. Best: es 4.11, it 4.25, pt 5.48, hi 6.81.
  Card warns normalization across 40 locales is imperfect -> real quality may be better. ja/ko/zh are CER.
- NOT comparable to Parakeet v3's 6.32% (English Open ASR Leaderboard). The card compares only against
  Parakeet RNNT 1.1B multilingual; for English NVIDIA points at its English-only model. No published
  head-to-head vs parakeet-tdt-0.6b-v3.
- Sizes (HF API): official repo 5.66 GB (safetensors 2.55, .nemo 2.37, q8_0.gguf 0.74);
  handy-computer GGUF Q4_K_M 0.50 / Q5_K_M 0.56 / Q6_K 0.62 / Q8_0 0.75 / F16 1.28;
  smcleod int8 ONNX ~0.67 deployed; onnx-community int4 ONNX 0.79 total incl. silero_vad.onnx;
  soniqo FP16 ONNX 1.31 GB.
- Integration note: our parakeet engine loads via onnx-asr's `nemo-conformer-tdt` type. Nemotron is
  cache-aware RNNT + prompt conditioning with a different export layout, so it will NOT drop into that
  path — needs a new engine (sherpa-onnx has ready int8 exports for the English variant at
  80/160/560/1120ms; the 3.5 multilingual only has community ONNX exports).
- Practical read: not an English upgrade, but it is the first 0.6B-class model that covers
  ar/hi/ja/ko/zh/vi/uk — i.e. the languages our own UI ships (ar/hi/zh/ru locales) and parakeet v3
  cannot do at all. Complement, not replacement.
