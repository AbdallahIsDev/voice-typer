# Debugging Voice Typer

Developer guide to debugging the Voice Typer desktop app. Covers the
Python backend, the Electron / Tauri host, and the IPC bridge between
them. For user-facing troubleshooting, see the README; for build /
release issues, see `RELEASING.md`.

---

## 1. Environment variables

These are the env vars you'll set most often when debugging. All are
read once at startup unless noted otherwise — set them before launching
the app.

### Backend (Python)

| Env var | Values | Effect |
|---|---|---|
| `VOICE_TYPER_DEBUG` | `1` / `0` | Enables DEBUG-level logging on the root logger. Equivalent to `--debug` CLI flag. |
| `VOICE_TYPER_QUIET` | `1` / `0` | Suppresses everything below WARNING. Overrides `VOICE_TYPER_DEBUG`. |
| `VOICE_TYPER_LOG_JSON` | `1` / `0` | Switches the log formatter from human-readable to structured JSON (one record per line). Useful when piping logs into `jq` or a log aggregator. |
| `VOICE_TYPER_CONFIG_DIR` | path | Override the data directory (default `%APPDATA%\voice-typer` / `~/Library/Application Support/voice-typer` / `$XDG_DATA_HOME/voice-typer`). Lets you run a second instance against a throwaway profile. |
| `VOICE_TYPER_IPC_TOKEN` | hex string | Override the per-session IPC auth token (SEC-018). Normally generated by the Electron main process; set explicitly when running the Python backend standalone (`python -m voice_typer.server.ipc_server`) and connecting a custom client. |
| `VOICE_TYPER_RESTART` | hex string | Restart-token proof (SEC-020). The Python backend reads this on startup; if it matches the persisted token, the Win32 single-instance mutex is bypassed so the new instance can run alongside the old one for ~5 s during handoff. |
| `VOICE_TYPER_STREAMING` | `0` | Disable hidden streaming transcription entirely. Use when investigating word-drop / duplicate-text bugs to rule out the streaming path. |
| `VOICE_TYPER_NO_TRAY` | `1` | Skip the pystray tray icon. Useful in headless / CI contexts where the tray would crash on missing GTK / AppKit. |
| `VOICE_TYPER_NATIVE_BINARY` | path | Override the native hotkey binary path (single binary). Bypasses the `VOICE_TYPER_NATIVE_DIR` / dev-source-tree lookup. |
| `VOICE_TYPER_NATIVE_DIR` | path | Directory containing all three native binaries (`{windows,macos,linux}-key-listener[.exe]`). Set by the Tauri host to `resourceDir/native/`. |
| `VOICE_TYPER_PREWARM_EXE` | path | Override the prewarm binary path (frozen `prewarm-<triple>[.exe]`). Bypasses `resolve_prewarm_exe()`. |
| `TAURI_SIDECAR` | `1` | Marks the process as running under the Tauri host. Skips ADR-0018 heartbeat-watchdog thread (supervisor owns liveness instead) and the Win32 single-instance mutex (Tauri `single-instance` plugin owns it). |

### Frontend (Electron host — legacy default)

> **Note:** these env vars are read by the Electron main process and
> are **ignored under the Tauri v2 host** (ADR-0020). Under Tauri,
> window lifecycle + DevTools gating is controlled by the Rust host's
> `tauri.conf.json` and capability files, not by these env vars. They
> are documented here for the legacy Electron build path only.

| Env var | Values | Effect |
|---|---|---|
| `VT_START_HIDDEN` | `1` | Create the main window hidden + skip-taskbar. Second-instance attempt shows it. Used by autostart to launch silently at login. |
| `NODE_ENV` | `production` / `development` | Electron / Vite convention. `production` disables DevTools + enables CSP enforcement. |
| `ELECTRON_DISABLE_SECURITY_WARNINGS` | `true` | Silences the Electron console warnings about `contextIsolation` / `sandbox` in dev. Don't set in production. |

### Frontend (Vite / electron-vite)

Standard Vite env vars (`VITE_*`) are exposed to the renderer via
`import.meta.env`. None are currently defined — the renderer reads all
runtime config from the backend via `get_config` IPC.

## 2. Log tags

The backend uses bracketed uppercase tags at the start of every log
message — `grep` for the tag to follow one subsystem through a log
file. The most useful tags for debugging:

| Tag | Subsystem |
|---|---|
| `[IPC]` | TCP / WebSocket IPC server, dispatch, rate limiter, heartbeat watchdog. |
| `[RECORDING]` | PortAudio capture, silence detection, streaming session lifecycle. |
| `[TRANSCRIPTION]` | faster-whisper / Qwen / Parakeet engine dispatch. |
| `[STREAMING]` | Hidden streaming transcription (overlapping windows, commit horizon, tail merge). |
| `[HOTKEY]` | Hotkey backend dispatch (native binary + pynput fallback). |
| `[HOTKEY-CAPTURE]` | Settings hotkey-picker capture dialog. |
| `[HOTKEY-WAYLAND]` | Wayland-specific hotkey backend. |
| `[TRAY]` | pystray tray icon + menu. |
| `[CLIPBOARD]` | Clipboard copy + paste + borrow/restore. |
| `[CLIPBOARD-SNAPSHOT]` | Multi-format clipboard snapshot/restore (ADR-0010). |
| `[VAD]` | Silero VAD noise gating. |
| `[AUDIO-PROC]` | Per-chunk audio processing (filter chain). |
| `[AUDIO-CHAIN]` | Filter chain assembly. |
| `[AUDIO_QUALITY]` | Per-recording quality report. |
| `[CONFIG]` | Config load / save / validation. |
| `[HISTORY_DB]` | SQLite history database. |
| `[CLEANUP]` | Shutdown controller — every subsystem released in order. |
| `[CRASH]` | Crash-recovery buffer flush. |
| `[CUDA-PROBE]` / `[CUDA-DLL]` | GPU detection + DLL loading. |
| `[CLOUD]` | Cloud ASR / LLM HTTP transports. |
| `[LLM_POLISH]` | LLM polishing pipeline. |
| `[LEVEL-MON]` | Microphone level monitor (continuous + test). |
| `[AUTOSTART]` | OS autostart install / remove. |
| `[LAUNCHER]` | Build-first launch strategy (autostart_launcher). |
| `[PREWARM]` | Prewarm pipeline + scheduling. |
| `[ASR_SETUP]` | Model auto-setup + dependency probing. |
| `[ASR_REGISTRY]` | ASR backend registry. |
| `[SEC]` / `[SECURITY]` | Security-related events (token, allowlist, file perms). |
| `[ENV]` | Env-var validation at startup. |
| `[FATAL]` / `[ATEXIT]` | Fatal error + atexit cleanup paths. |

Filter live with:

```bash
tail -F <DATA_DIR>/logs/voice-typer.log | grep --line-buffered '\[IPC\]\|\[RECORDING\]'
```

Or, with JSON logging (`VOICE_TYPER_LOG_JSON=1`):

```bash
tail -F <DATA_DIR>/logs/voice-typer.log | jq 'select(.tag == "IPC")'
```

`<DATA_DIR>` is the platform-specific data directory resolved by
`voice_typer.server.config._config_dir()` (see
[`docs/home-directory.md`](home-directory.md) for the per-platform layout:
`%APPDATA%\voice-typer` on Windows, `~/Library/Application Support/voice-typer`
on macOS, `$XDG_DATA_HOME/voice-typer` on Linux).

## 3. faulthandler

The backend enables `faulthandler` on startup (in `voice_typer/server/ipc_server.py`'s `main()` and `voice_typer/server/app.py`'s `VoiceTyperApp._enable_faulthandler()` helper — RACE-018):

- `faulthandler.enable()` — prints a Python traceback to `stderr` on
  `SIGSEGV` / `SIGFPE` / `SIGABRT` (would otherwise produce no Python
  stack on a C-extension crash).
- `faulthandler.dump_traceback_later(timeout, repeat=True)` — dumps all
  thread tracebacks every `timeout` seconds. Used to diagnose
  deadlocks (e.g. a thread stuck holding the recorder lock).
- `faulthandler.register(SIGUSR1)` — on POSIX, sending `SIGUSR1` to
  the backend PID dumps every thread's traceback to `stderr` without
  killing the process. Use `kill -USR1 <pid>` from another terminal.

On Windows, `faulthandler` works for `SIGSEGV` etc. but
`dump_traceback_later` is unreliable (uses a watcher thread that
doesn't always wake up); attach `windbg` or VS instead.

## 4. Single IPC handler isolation

When debugging a single IPC command (e.g. `set_config` regression), it
helps to exercise just that handler without bringing up the whole app.
The pattern:

```python
# tests/handlers/conftest.py already does this — copy the fixture.
from voice_typer.server.handlers.config_handlers import handle_get_config
from tests.handlers.conftest import make_app  # or build a minimal mock

app = make_app()  # mocked hardware, real Config / handlers
result = handle_get_config(app, {})
print(result)
```

Every handler lives in `voice_typer/server/handlers/<domain>_handlers.py`
and follows the signature `handler(app, data) -> dict`. They're
registered in `_COMMAND_REGISTRY` (see
`voice_typer/server/ipc/dispatch.py`); you can call them directly
without going through the TCP server.

For end-to-end IPC debugging without a real Electron host, use the
`tests/fixtures/ipc_test_helpers.py` helpers — they spin up the real
`IPCServer` on an ephemeral port, authenticate with a known token, and
give you a `send(cmd)` / `recv()` pair.

## 5. Common failure modes

### "Hotkey doesn't fire"

1. Check `[HOTKEY]` log lines for `native binary not found` — install
   the compiled binary (`scripts/build/compile_native.sh`) or set
   `VOICE_TYPER_NATIVE_BINARY`.
2. On macOS, check `check_accessibility` IPC response — if `false`,
   grant Accessibility in System Settings → Privacy & Security →
   Accessibility, then restart.
3. On Linux, check `ls -l /dev/input/event*` — the user must be in the
   `input` group (`sudo usermod -aG input $USER` + re-login).
4. If `[HOTKEY]` shows `fallback to pynput` — the native binary died
   and we fell back. Check `[HOTKEY]` for the crash reason.

### "Transcription returns empty / wrong text"

1. Set `VOICE_TYPER_STREAMING=0` and re-test — if the bug disappears,
   it's the streaming tail-merge path (see
   `docs/duplicated-text.md` for the known timestamp-drift bug).
2. Check `[TRANSCRIPTION]` for `CUDA OOM` / `fallback to CPU` — a
   silently-fallen-back CPU model may transcribe differently.
3. Check `[VAD]` for `rejected as hallucination` — the hallucination
   detector may be too aggressive on near-silence audio. Temporarily
   disable via `config.hallucination_rejection = False`.
4. Run `tests/manual/runtime_proof.py` to verify the engine end-to-end
   with a known-good fixture.

### "App won't start"

Two distinct host paths can produce an "app won't start" symptom.
 Pick the sub-path that matches the host you're running.

#### Sub-path A — Electron host (legacy default)

1. Check the Electron main-process log
   (`<DATA_DIR>/logs/electron-main.log` — see [`docs/home-directory.md`](home-directory.md)
   for the per-platform `<DATA_DIR>` layout) for
   `[IPC] failed to connect` — backend didn't come up.
2. Check the backend log (`voice-typer.log`) for `[FATAL]` /
   `[ENV]` lines — env-var validation may have killed it before IPC
   bound.
3. Try launching the backend standalone: `python -m
   voice_typer.server.ipc_server --debug`. If it starts, the issue is in
   the Electron spawn path.
4. Check for a stale single-instance mutex: on Windows, run
   `tasklist | findstr voice-typer` — if a ghost process is holding
   the Win32 mutex, `taskkill /F /PID <pid>` it.

#### Sub-path B — Tauri host (ADR-0020)

1. Check `<DATA_DIR>/logs/voice-typer.log` for
   `{"event":"server_started","port":N}` — if absent, the sidecar
   didn't bind the WebSocket.
2. Check the Tauri devtools console (right-click → Inspect) for supervisor backoff messages.
3. Run the sidecar standalone: `python -m voice_typer.server.ipc_server
   --ws` — should print `{"event":"server_started","port":N}` to
   stdout.
4. Set `RUST_LOG=debug` before launching the Tauri binary to get
   verbose `tokio-tungstenite` logs.

### "Clipboard not restored after paste"

1. Check `[CLIPBOARD-SNAPSHOT]` for `snapshot captured N formats` —
   should be ≥1 on Windows / macOS. On Linux, only text is captured
   (documented limitation).
2. Check `[CLIPBOARD]` for `restore scheduled in Xms` — the restore
   runs on a daemon thread after `clipboard_restore_delay_ms` (default
   150 ms). If you switch focus within that window, the restore may
   land in the wrong window.
3. Check `[CLIPBOARD-AUDIT]` for `clipboard modified externally` —
   another app (clipboard manager, sync tool) may have written between
   our borrow and restore.

### "Crash recovery not prompting on restart"

1. Check `[CRASH]` for `recovery file written` — should fire on every
   successful transcription. If absent, the crash-recovery worker
   thread died.
2. Check `<DATA_DIR>/crash_recovery/voice-typer-recovery.json` —
   should be valid JSON with a `pending` array. If corrupt, the app
   silently ignores it on next launch (logged at WARNING).
3. The prompt only fires if there's ≥1 unpasted transcription. If you
   pasted successfully, the entry is removed from `pending` and no
   prompt appears.

## 6. Profiling

For startup-time profiling, see `bench/bench_startup.py` and
`bench/COLDSTART_REPORT.md`. The COLDSTART report documents the lazy-
import strategy that brought cold-start time from ~5 s down to ~1.5 s.

For per-recording latency, set `VOICE_TYPER_DEBUG=1` and look for
`[TRANSCRIPTION] transcribed in Xms` log lines. The breakdown is:

- `Recorder.stop()` returns the audio array (typically <10 ms).
- `TranscriptionEngine.transcribe()` does the actual ASR (100–2000 ms
  depending on model size + audio length + GPU/CPU).
- `clean_transcribed_text()` post-processing (typically <20 ms).
- `ClipboardManager.copy()` + `paste()` (typically <30 ms).

## 7. Getting help

- **Logs**: always attach `<DATA_DIR>/logs/voice-typer.log` (and
  `electron-main.log` if Electron-side) to bug reports. `<DATA_DIR>` is
  the platform-specific data directory — see [`docs/home-directory.md`](home-directory.md)
  for the per-platform layout. Redact API keys first — the `PIIRedactionFilter`
  should have already done this, but verify.
- **Repro**: a minimal `pytest` reproduction is gold. The handler
  isolation pattern (§4) makes this tractable even for IPC bugs.
- **Architecture**: read `docs/ARCHITECTURE.md` first — most "why does
  X behave like Y" questions are answered there.
