# ADR 001: Architecture Decision Records

## Status

Accepted

## Context

We need a mechanism to document important architectural decisions and their
rationale so that future contributors understand why certain choices were made.

## Decision

We will use Architecture Decision Records (ADRs) as described by Michael Nygard.
Each ADR will follow this template and be stored in `docs/adr/`.

## Consequences

- All significant architectural decisions will be documented
- New contributors can understand the rationale behind key decisions
- ADRs are immutable once accepted (superseded by new ADRs)
